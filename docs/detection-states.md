# 🔍 四态判定：连不上 ≠ 服务挂了

> 这一页是我们和别的方案最大的区别。**大多数监控会吵你，因为它分不清"你关机了"和"服务挂了"。**

---

## 问题

假设你的哨兵每 10 分钟检查一次。某天你：

- 出差，笔记本关机
- 家里断网
- 重启路由器

**任何正常的监控都会报警** —— 连续 N 次连不上。

于是你手机上收到 6 条"服务器挂了！"。你回家一看：**什么都没坏，是你自己关的机。**

**这就是"告警疲劳"的来源** —— 报警太多 → 你开始无视 → 真故障也漏了。

---

## 关键洞察

**"连不上"不是故障。它是"未知"。**

一个健康的监控必须能区分**四种**状态：

| # | 状态 | 现象 | 该怎么办 |
|---|---|---|---|
| ① | **本机不可达** | 连接超时/拒绝/网络不可达 | **静默**（大概率是你自己关的） |
| ② | **配置异常** | 连上了，但认证失败 / 命令被拒 | 提示一次 |
| ③ | **健康** | 连上 + `healthy: true` | 静默（若上次是坏的 → 提示"已恢复"） |
| ④ | **真故障** | 连上 + `problems` 非空 | 提示 → 无人回执则自修 |

**一句话规则：只有「能连上 + 有故障」才吵用户。**

---

## 各状态的详细处理

### ① 本机不可达 → 默认静默

```python
try:
    result = ssh_run("verify", timeout=10)
except (Timeout, ConnectionRefused, NetworkUnreachable):
    state = "unreachable"
```

**为什么静默**：99% 的情况是你自己关机/断网/在飞机上。

**但完全静默也有风险** —— 万一真挂了（硬件、系统崩了）呢？

**折中**：

- **连续不可达**超过阈值（默认 **2 小时**）→ 提示**一次**
- 提示里带上**已不可达多久**
- 之后**不重复**（除非状态跳变）

```
🔌 已 2 小时 15 分钟连不上主机。
   如果这是你自己关机/断网，忽略这条；
   如果没关，可能需要现场看一下。
```

**阈值怎么定**：看你的使用习惯。

- 每天关机的人 → 阈值调大（比如 8 小时）
- 7×24 在线的服务器 → 阈值调小（比如 30 分钟）

### ② 配置异常 → 提示一次

```python
except AuthenticationFailed:
    state = "config-error"
```

**这是真问题**（钥匙被删了？`sshd` 改了？账号被锁了？），但**不是"服务挂了"**。

提示文案要**分开**，否则你会去查错方向：

```
🔑 能连上主机，但认证/命令被拒。
   这通常不是服务故障，而是 SSH 配置变了。
```

**去重**：同一种配置错误**只提示一次**，别每次检查都吵。

### ③ 健康 → 静默（除非刚恢复）

```python
if payload.get("healthy"):
    if last_state in ("unreachable", "config-error", "unhealthy"):
        notify("✅ 已恢复")     # 跳变才提示
    state = "healthy"
```

**"已恢复"很重要** —— 否则你不知道它什么时候好的，会一直惦记。

### ④ 真故障 → 提示 → 无回执则自修

```python
if payload.get("problems"):
    state = "unhealthy"
    fingerprint = hash(json.dumps(payload["problems"], sort_keys=True))
    if fingerprint != last_fingerprint:
        notify(f"⚠️ 检出 {len(problems)} 个问题", detail=problems)
        start_receipt_timer(minutes=30)
```

**两个关键机制**：

**a) 指纹去重**

同一个问题（指纹相同）**不重复提示**。只有问题**变了**才再吵。

```python
fingerprint = sha256(sorted(problems))   # 问题集合的指纹
```

这样"磁盘 85%"不会每 10 分钟报一次；变成"磁盘 92%"才报。

**b) 回执机制**

提示之后等 N 分钟（默认 30）等**人**回执。

- 有人回 → 人接手，哨兵退让
- 没人回 → **它自己上手修**（`exec`）

```
⚠️ 检出 1 个问题：example.service inactive
   30 分钟内没回应的话，我会自己尝试修复。
```

**这一条是"兜底"的核心** —— 你在睡觉/开会/没看手机，故障照样被处理。

## 怎么区分「本机断网」和「服务挂了」

光靠"连不上"分不出来 —— 因为连不上就是连不上。

**做法**：让 `verify` 的 JSON 带上**自证字段**：

```json
{
  "boot_id": "3f2a…",        // 本次开机唯一 id
  "uptime_h": 0.4,           // 开机多久
  "net_ok": true,            // 它自己能不能出网
  "frp_ok": true             // 隧道通不通
}
```

有了这些，你就能回答：

| 现象 | 推断 |
|---|---|
| 连不上，但上次 `uptime_h` 很大 | 可能真挂了（不是刚重启） |
| 连上了，`uptime_h` 很小 + `boot_id` 变了 | **刚重启过** → 服务没起来是正常的，等一会 |
| 连上了，`net_ok: false` | 本机没网 → 不是服务的错 |
| 连上了，`frp_ok: false` | 隧道断了 → 修隧道，不是修服务 |

**`boot_id` 是关键** —— 没有它，你无法区分"服务挂了"和"刚开机服务还没起"。

## 状态机全图

```
                    ┌─────────────┐
      ┌────────────►│  unreachable│◄────────┐
      │             └──────┬──────┘         │
      │  超阈值提示一次      │ 连上了          │ 又断了
      │  （带时长）         ▼                │
      │             ┌─────────────┐         │
      │             │ config-error│         │
      │             └──────┬──────┘         │
      │  提示一次           │ 认证通过        │
      │                     ▼                │
      │             ┌─────────────┐         │
      └─────────────┤   healthy   │         │
                    └──────┬──────┘         │
                           │ problems 非空   │
                           ▼                │
                    ┌─────────────┐         │
                    │  unhealthy  ├─────────┘
                    └──────┬──────┘
                           │ 指纹变了 → 提示
                           │ 30 分钟无回执 → 自修
                           ▼
                    ┌─────────────┐
                    │  self-heal  │
                    └─────────────┘
```

**只有两条边会触发通知**：

- `unhealthy` 且**指纹变了**
- 任何状态**跳变**（包括恢复到 healthy）

## 提示文案模板

好的告警应该**自带判断**，而不是甩一堆原始数据。

**坏**：
```
ERROR: ssh timeout to host
```

**好**：
```
🔌 已 2 小时 15 分连不上。
   你自己关机/断网 → 忽略；
   没关 → 可能要看一眼。
```

**坏**：
```
service example is inactive
```

**好**：
```
⚠️ example.service 停了（inactive）
   这台是常驻服务，不正常。
   30 分钟没回应我会自己试着重启。
```

**原则**：**告诉对方"这条要不要管"**，别让它自己判断。

## 实现要点

### 1. 状态要持久化

```json
// ~/.local/state/sentinel.json
{
  "state": "unhealthy",
  "since": "2026-10-15T00:12:33+08:00",
  "last_fingerprint": "a3f2…",
  "last_notify_at": "2026-10-15T00:12:35+08:00",
  "receipt_deadline": "2026-10-15T00:42:35+08:00",
  "unreachable_since": null
}
```

**没有持久化 = 每次检查都当第一次** → 告警风暴。

### 2. 通知要走"能到人"的通道

⚠️ 这条我们踩过坑：**别假设"发出去 = 人会看到"**。

不同通道的现实：

| 通道 | 人会看到吗 |
|---|---|
| Telegram/Slack 推送 | ✅ 会（有提醒） |
| 邮件 | ⚠️ **看习惯** —— 我们实测过：对面的 AI **不会主动查邮箱** |
| 写进某个文件 | ❌ 不会 |
| 系统日志 | ❌ 不会 |

**发之前先确认：这条通道真的会被人看到吗？**

### 3. 幂等

同一个状态跑 100 次 → 只提示 1 次。

```python
if state == last_state and fingerprint == last_fingerprint:
    return   # 什么都不做
```

### 4. 时钟

用**单调时间**判断"多久了"（避免 NTP 跳变），用**墙上时间**写日志。

## 和别的方案对比

| 方案 | 连不上时 | 同一问题重复 | 有人回执吗 |
|---|---|---|---|
| 普通 uptime 监控 | 🔴 报警 | 🔴 每轮都报 | ❌ |
| 大多数 self-healing agent | 🔴 报警 | ⚠️ 部分去重 | ❌ |
| **本项目** | ✅ 静默（超阈值才提示） | ✅ 指纹去重 | ✅ 有 |

**"连不上静默"这一条，我们翻遍了同类项目，没找到一个做的。**
